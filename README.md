# Попути

Локальное веб-приложение авторских туров на Python 3.13, Django 5.2, PostgreSQL, HTML, CSS и JavaScript. Интерфейс вдохновлён композицией YouTravel.me: большая фотография, поиск путешествия, карточки направлений и лаймовые акценты. Название, тексты и оформление проекта самостоятельные.

## Что работает

- Главная страница с демонстрационными турами, поиском по названию и направлению, категориями, диапазонами дат и цены, сортировкой.
- Карточка тура с программой, организатором, выездами, ценой и доступными местами.
- Регистрация с автоматическим входом, вход по логину и паролю, выход через POST.
- Бронирование выбранного количества мест с мгновенным подтверждением без онлайн-оплаты.
- Отдельная доступность каждого выезда, защита от переполнения при конкурентных запросах, повторная отправка одного запроса без второй брони.
- Личный список подтверждённых и отменённых броней, отмена до начала выезда с однократным возвратом мест.
- Административный интерфейс Django для туров и выездов. Пользовательский кабинет организатора ещё не реализован.

## Запуск в Windows

Откройте PowerShell в папке проекта:

```powershell
.\scripts\start.ps1
```

Скрипт подготавливает окружение при его отсутствии, запускает локальный PostgreSQL, применяет миграции, добавляет демонстрационные туры и запускает Django на **http://127.0.0.1:8000/**. Для другого порта используйте `-Port 8001`.

Сейчас виртуальное окружение, PostgreSQL и изображения уже подготовлены. При первом запуске в другой копии нужен установленный uv и доступ в интернет для загрузки Python, зависимостей и переносимого PostgreSQL с официального сайта EDB.

Страница доступна на этом компьютере. Привязка к `127.0.0.1` не открывает сайт на других устройствах локальной сети. Остановка Django — Ctrl+C в его терминале.

Если база уже запущена, можно запускать только сайт:

```powershell
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

## Локальная база данных

По умолчанию используется PostgreSQL на `127.0.0.1:54329`, база и пользователь `poputi`, пароль для локальной разработки `poputi_dev`. Другой адрес задаётся через `DATABASE_URL` в `.env`; образец — `.env.example`.

Переносимый PostgreSQL скачивается в `.tools/`. На Windows его рабочая копия и данные по умолчанию находятся в папке `poputi-<идентификатор проекта>` внутри системного Temp: это обход проблемы PostgreSQL с кириллицей в пути. Для постоянного расположения добавьте `POPUTI_RUNTIME_DIR=E:/poputi-data` в `.env` проекта. Переменная указывает на корень, содержащий `data/` и `postgres/`, а не на сам `data/`.

Перед сменой пути остановите PostgreSQL и скопируйте весь существующий каталог `poputi-<идентификатор проекта>` в новое место. Не задавайте новый пустой каталог до копирования: стартовый скрипт создаст в нём новую пустую базу. Исходную копию сохраните до проверки данных в новом расположении. Адрес подключения и `DATABASE_URL` при таком переносе не меняются.

Остановить переносимый PostgreSQL:

```powershell
.\.venv\Scripts\python.exe scripts\setup_local.py stop
```

Вариант с Docker:

```powershell
docker compose up -d db
.\scripts\start.ps1 -ExternalDatabase
```

Переносимая база и контейнер используют один порт; одновременно запускайте один вариант.

## Демонстрационные данные и аккаунты

Команда `seed_demo` добавляет шесть туров и 18 будущих выездов. Повторный запуск сохраняет существующие брони. Зарегистрируйте собственный аккаунт через интерфейс. Организатор демонстрационных туров не имеет пароля для входа и административных прав.

Если нужен доступ к администрированию:

```powershell
.\.venv\Scripts\python.exe manage.py createsuperuser
```

После создания своего администратора откройте http://127.0.0.1:8000/admin/.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Проверки используют отдельную базу `test_poputi`, которую создаёт и удаляет pytest-django. PostgreSQL должен работать; у тестового пользователя базы должно быть право создавать базы. Рабочие данные приложения не используются тестами.

Текущий результат: **56 успешных проверок** — 39 примеров из существующих Gherkin-файлов и 17 HTTP/интеграционных проверок. Конкурентные сценарии выполняются в отдельных потоках и соединениях PostgreSQL.

Автоматизированы четыре файла: регистрация, вход/выход, создание и отмена брони. Остальные `.feature` файлы остаются спецификациями для следующих этапов. Карта сценариев находится в `features/README.md`.

Через браузер также проверен путь: регистрация → выбор тура → расчёт на двух участников → подтверждение → отмена.

## Структура

- `accounts/` — пользователь, формы и страницы регистрации и входа.
- `tours/` — туры, выезды, каталог, фильтрация и демонстрационные данные.
- `bookings/` — брони и транзакционные операции резервирования и возврата мест.
- `templates/` и `static/` — страницы, стили, JavaScript и локальные изображения.
- `features/` — Gherkin-сценарии на русском языке.
- `tests/bdd/` — реализации шагов и привязка сценариев к pytest-bdd.
- `tests/test_web.py` — проверки HTTP-путей, доступа, форм и ограничений данных.

## Изображения

Иллюстративные фотографии загружены с Unsplash и не являются фотографиями конкретных демонстрационных поездок. Источники изображений перечислены в `scripts/setup_local.py`. Все изображения обслуживаются локально из `static/img/`; внешние сервисы для показа страниц не нужны.

Это локальная версия для разработки. Конфигурация рабочего размещения, онлайн-оплата, кабинет организатора и автоматизация остальных спецификаций относятся к следующим этапам.
